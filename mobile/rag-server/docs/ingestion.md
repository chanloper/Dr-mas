# 공개자료 등록 지침

이 프로젝트는 기관 웹사이트 크롤러나 공공데이터 API를 포함하지 않습니다. 엔드포인트를 추측하지 않으며 실제 의료문서를 수집/재배포하지 않았습니다. 예제 URL은 예약된 example.org 테스트 주소입니다.

1. 질병관리청·식약처·공식 의료기관의 해당 원문 페이지를 직접 확인합니다. 사이트 이름만으로 재사용 가능하다고 판단하지 않습니다.
2. 해당 페이지/파일에 적용되는 이용약관·공공누리 유형·저작권·제3자 권리·API 약관·접근 제한을 확인합니다. robots.txt만으로 재사용 권한이 생기지 않습니다.
3. 외부 AI 전송, 로컬 보관, 상업적 서비스 이용, 재배포, 변경 허용 여부를 별도로 확인합니다. 불명확하면 permitted로 등록하거나 대량 수집하지 말고 기관에 확인합니다.
4. 공개 문서이며 환자 이름·식별자·진료기록·개별 복약기록이 포함되지 않았는지 사람이 확인합니다. PDF/OCR은 사람이 내용과 문단 순서를 검수한 UTF-8 텍스트로 수동 변환합니다. PDF 파서는 미구현입니다.
5. 템플릿에 고유 ID, 원문 제목/기관/직접 URL, 발행/갱신/수집일, 분류, 본문을 기록합니다. rights.terms에는 약관/라이선스 URL과 허용 범위, rights.checkedAt에는 확인일을 적습니다. 법적 판단을 코드가 자동 검증하지 않습니다.
6. 확인된 자료에 한해 rights.permission을 permitted로 설정하고 import합니다. 외부 전송이 허용되지 않는 자료는 이 live 경로에 등록하지 않습니다.
7. 최신성 검토 일정은 운영자가 관리합니다. 원문 변경 시 같은 ID로 등록합니다. 철회된 문서는 delete하고 필요한 경우 별도 보관/삭제 정책을 적용합니다.

분류 값: disease, medicine, medication, lifestyle, caregiver. 원문이 없는 날짜를 추정하지 마세요. 본문 해시는 정확한 UTF-8 문자열 기준이므로 공백 변경도 본문 변경으로 처리합니다. 모델 캐시에 과거 Chunk 임베딩이 남을 수 있으므로 자료 철회 시 운영 정책에 따라 전체 캐시도 비우세요. 원문 본문/출처의 삭제는 delete에서 처리합니다.

공공데이터포털을 추가할 때는 실제 서비스명, 공식 요청/응답 명세, 키 취급, 제한과 이용 허락을 먼저 문서화하고 별도 수집 어댑터와 테스트를 추가하세요.
