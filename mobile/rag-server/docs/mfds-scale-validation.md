# e약은요 20~50행 확대 검증 준비

확인일: 2026-11-02. 이번 작업은 Mock 테스트와 공식 자료 조사만 수행했습니다. **실제 식약처 수집 0회, 실제 Gemini 호출 0회**입니다. 기존 5행 실데이터와 그 보고서는 수정하지 않습니다.

## 수집 범위와 예산

수집 한도는 고유 품목 수가 아닌 **원본 행 수**입니다. 이미 확인한 이미지 변형 행 때문에 고유 품목은 이보다 적을 수 있습니다. 중복을 보충하려고 추가 페이지를 요청하지 않습니다.

| 승인 범위 | 페이지 크기 | 요청 페이지 | 정상 호출 수 | 재개·재시도 포함 최대 시도 수 |
|---|---|---|---|---|
| 20행 | 10행 | 1~2 | 2회 | 6회 |
| 30행 | 10행 | 1~3 | 3회 | 9회 |
| 40행 | 10행 | 1~4 | 4회 | 12회 |
| 50행 | 10행 | 1~5 | 5회 | 15회 |

API 결과가 한도보다 적으면 일찍 종료할 수 있습니다. 서버가 요청 크기와 다른 페이지 번호·건수·과다 행을 반환하면 실패 처리합니다. 임의의 25행이나 51행 등은 지원하지 않습니다. 페이지 크기 10을 고정해 재개 중 페이지 경계가 달라지는 문제를 방지합니다.

- 개별 HTTP 시도: 최대 10초, 수신 본문 2,000,000바이트.
- 페이지별: 최대 3회 시도. HTTP 429/5xx, API 01/05/23만 제한 내 재시도합니다. 키·권한·일일 한도 오류, 네트워크 오류, 클라이언트 시간초과는 자동 재시도하지 않습니다.
- 호출 간격: 최소 1.1초. 확대 수집에서는 이전 시도가 종료된 시각도 저장해 재개 시 간격을 유지합니다.
- 전체 승인 범위: 위 표의 시도 예산을 디스크에 **전송 전 예약**합니다. 실패·중단도 예산을 소비하며 재실행으로 초기화하지 않습니다. 페이지별 예산도 누적합니다.
- 시간 창: 최초 시작 후 **15분**을 디스크에 기록합니다. 재개해도 연장하지 않고, 만료되면 추가 호출을 막습니다. 만료 후 검토·재승인·별도 복구 설계가 필요합니다. 자동 초기화 명령은 없습니다.
- 동일 범위의 동시 실행은 `run.lock`으로 차단합니다. 강제 종료 후 남은 잠금은 자동 삭제하지 않습니다. 기존 README의 stale lock 절차에 따라 프로세스 종료를 확인하고 검토해야 합니다. 호출 예산·원본 파일은 지우지 않습니다.

## 사용자가 실행하는 절차

먼저 작업 경로를 설정합니다.

```powershell
Set-Location C:\MAS\Dr-mas\mobile\rag-server
```

네트워크 없이 계획을 확인합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\mfds-pilot.ps1 -MaxRows 20 -Preflight
```

**실제 수집은 이후 사용자가 직접 승인해 실행할 때만 수행합니다.** 키를 명령행·파일에 쓰지 않고 숨김 입력으로 받으며, `COLLECT 20`을 입력해야 계속합니다. 키는 자식 프로세스의 `DATA_GO_KR_SERVICE_KEY`로만 전달하며 스크립트 종료 시 이전 환경을 복원합니다. `-ExecutionPolicy Bypass`는 이번 새 프로세스에만 적용됩니다.

페이지 1개만 먼저 실행해 결과를 검토하려면:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\mfds-pilot.ps1 -MaxRows 20 -Pages 1
```

예상 정상 HTTP 호출 1회, 이 페이지의 최대 시도는 3회입니다. 첫 페이지의 원본·정제·RAG 전달·보고서 저장 후 정상 종료합니다. 같은 명령을 다시 실행하면 확인 문구와 숨김 입력을 거쳐 **다음 미완료 페이지**부터 이어집니다. 두 번째 실행은 정상 1회, 두 실행을 합쳐 정상 2회·최대 6회입니다. `-Pages`는 한 번 실행할 페이지 수이며 전체 승인 한도는 늘리지 않습니다.

처음부터 최대 50행을 승인하려면:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\mfds-pilot.ps1 -MaxRows 50
```

`COLLECT 50` 확인과 숨김 키 입력이 필요합니다. 정상 5회, 누적 최대 15회입니다. 20행과 50행 범위는 **별도 승인·별도 저장소**입니다. 20행 뒤 50행을 새로 실행하면 페이지 1부터 다시 읽으므로 정상 호출 합계는 7회가 될 수 있습니다. 기존 5행·20행에서 이어지는 전역 증분 수집이라는 의미가 아닙니다. 한 범위가 완료되면 같은 범위의 재실행은 추가 페이지를 호출하지 않습니다.

상태와 저장 자료 검증은 네트워크 없이 실행할 수 있습니다. 키가 필요하지 않습니다.

```powershell
npm.cmd run mfds:batch -- status --max-rows=20
npm.cmd run mfds:batch -- verify --max-rows=20
```

서버 비밀 환경이 이미 설정된 경우를 위한 직접 CLI도 있습니다. 이 명령에는 별도 확인 프롬프트가 없으므로 최초 수동 테스트에는 위 PowerShell 스크립트를 권장합니다.

```powershell
npm.cmd run mfds:batch -- collect --max-rows=20 --pages=1 --approve-live --portal-approved
```

## 저장·재개·증분 처리

확대 범위별 저장소는 `data/mfds-scale-20/`, `data/mfds-scale-30/`, `data/mfds-scale-40/`, `data/mfds-scale-50/`입니다. 기존 `data/mfds-pilot/`에는 쓰지 않습니다. 모두 개발용 로컬 저장소이며 Git ignore 대상입니다.

- `control/state.json`: 승인 한도, 시작·마감 시각, 전체·페이지별 누적 HTTP 시도 수, 호출 간격 기록. 키나 요청 URL은 저장하지 않습니다.
- `ingestion/state.json`: 내용 해시로 식별하는 원본 스냅샷, 정제 품목, 페이지 체크포인트, RAG 등록 대기열.
- `rag/state.json`: 품목별 문서·청크. 모든 문서가 pending이며 벡터와 Gemini 사용량은 0이어야 합니다.
- `verification-report.json` / `.html`: 성공적으로 전달한 페이지마다 생성하는 원문 대조 보고서. 원본 행·고유 품목·중복·누락/null·출처 페이지를 구분합니다.
- `batch-result.json` / `batch-failure.json`: 최근 실행 결과 또는 안전한 오류 코드. 실패 시 이전 정상 페이지의 보고서는 남습니다.

원본·정제·체크포인트·등록 대기열은 페이지 단위로 커밋합니다. 실패한 페이지는 체크포인트를 전진시키지 않습니다. HTTP 성공 후 검증·저장 전에 중단되면 같은 페이지를 다시 요청할 수 있지만 이전 시도 예산은 소비된 상태입니다. 완료 페이지에서 RAG 전달만 실패한 경우에도 재개가 먼저 대기열을 전달하며, 그 목적으로 새 API 요청을 하지 않습니다. 정확히 한 번 전송을 보장하는 구조가 아니라 제한된 예산 안의 재시도와 멱등 등록 구조입니다.

품목코드와 **수집 시각을 제외한 정제 해시**로 변경을 감지합니다. 미변경 품목은 lastSeenAt만 바꾸고 RAG에 다시 등록하지 않습니다. 효능·주의사항 등 정제 값이 바뀐 품목만 갱신합니다. 이미지 등 미매핑 원본 필드만 바뀐 경우 새 원본을 보존하고 문서 본문은 갱신하지 않습니다. Mock 재스캔에서 이 동작을 검증했습니다. 일반 `collect`는 새 jobId로 증분 비교를 지원하지만, 이 확대 검증 CLI는 완료 범위를 자동 재스캔하거나 새 범위로 초기화하지 않습니다. 정기 재스캔은 별도 승인·예산·이력 관리가 필요한 후속 운영 작업입니다.

현재 e약은요 명세에는 고정 스냅샷 토큰·정렬 보장·삭제 이력 피드가 없습니다. 페이지 사이 전체 결과 수가 바뀌면 보고서를 실패시키고 다음 실행의 추가 요청도 막습니다. 같은 품목코드의 정제 값이 페이지 사이 충돌해도 검증이 실패합니다. 전체 결과 수가 같으면서 순서만 바뀌는 경우의 누락까지 보장하지는 않습니다. 보고서가 검증을 통과한 것은 수집한 범위의 원문 대조 결과이며 전체 데이터베이스의 일관성을 보장하지 않습니다.

## 삭제·취하와 권한 조사

확인일 2026-11-02. 다음은 공식 자료에서 확인한 내용과 그에 따른 구현 판단입니다.

1. [e약은요 공식 명세](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15075057)는 품목코드·복약 문항·공개/갱신일·이미지를 제공하지만 삭제·취소·취하 상태, 삭제 시각, 변경 이벤트 유형을 제공하지 않습니다. 공급실적이 있는 일반의약품의 개요 데이터라는 제공 범위도 전체 허가 상태 조회와 다릅니다. **현재 API만으로 삭제·취하를 확정할 수 없다는 구현 판단**이며, `deletionStatus=unverified`로 보고하고 미발견 품목을 삭제하지 않습니다. updateDe의 범위 비교 의미나 조회 누락을 삭제 신호로 추측하지 않습니다.
2. [식약처 의약품안전나라의 공식 의약품 검색 화면](https://nedrug.mfds.go.kr/searchDrug?itemName=%ED%83%81%EC%84%BC&searchYn=true)에는 별도의 취소/취하 및 일자 항목이 표시됩니다. 이는 e약은요 응답 필드라는 근거가 아니며, 이번 코드에서 해당 화면을 수집하거나 다른 API를 호출하지 않습니다. 별도 공식 허가정보 명세·코드 연결 검증이 후속 과제입니다.
3. e약은요 데이터셋 페이지는 무료·이용허락범위 제한 없음으로 표시하며 개발계정 트래픽 10,000, 운영 심의 절차를 안내합니다. [공공데이터포털 공식 이용정책](https://www.data.go.kr/ugs/selectPortalPolicyView.do)은 제3자 권리가 포함된 자료의 이용허락과 표시된 이용 조건 확인을 요구합니다. 이 자료들에서 e약은요의 Gemini 전송을 특정하여 검토한 내용을 확인하지 못했습니다. 이는 외부 전송이 금지된다는 단정이 아니라 운영 검토가 완료되지 않았다는 의미입니다.
4. [Google Gemini API 공식 추가 약관](https://ai.google.dev/gemini-api/terms)은 무료·유료 서비스의 입력 데이터 이용 조건을 구분하며 임상 사용·의료 조언 등에 대한 제한도 명시합니다. 의료 RAG의 용도와 서비스 계정 조건을 별도로 검토해야 합니다. 단순히 공공데이터 API 승인을 받았다는 이유로 외부 AI 전송 가능 판정을 내리지 않습니다.

따라서 모든 자료의 `permission=pending`, `externalAiPermission=unverified`를 유지합니다. 이번 명령에는 임베딩·생성 호출이나 권한 승격 기능이 없습니다.

## 검증

Mock으로 20행 페이지 경계 중단/재개, 50행 중간 네트워크 실패 후 재개, 페이지 사이 이미지 중복, 누락/null 구분, 누적 예산·마감·설정 변경 차단, 완료 범위의 미전달 RAG 복구, 변경된 정제 품목만 갱신, 원본 전체 결과 수 변동 차단, PowerShell 승인·비밀값 보호를 검사합니다. 실제 서비스의 20~50행 동작은 아직 실행하지 않았습니다.

최종 결과: **총 76개, 통과 75개, 실패 0개, 건너뜀 1개**(PowerShell 7 미설치). `npm.cmd run check`, `npm.cmd run lint` 모두 통과했습니다. PowerShell의 `-MaxRows 50 -Preflight` 실제 실행에서도 `networkRequests=0`, `maxPages=5`, `maxAttempts=15`, `permission=pending`, `geminiEnabled=false`를 확인했습니다. 기존 5행 수집의 원본/정제 저장소·RAG 저장소·예약·최초 실행 결과 파일은 이전 SHA-256과 모두 일치합니다.

현재 LocalRepository는 전체 JSON 스냅샷을 읽고 씁니다. 이번 규모의 검증에는 사용할 수 있지만 대규모 운영 DB·원본 객체 저장소의 대체가 아닙니다.
