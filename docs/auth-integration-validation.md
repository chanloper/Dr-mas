# 인증 통합 검증 결과

검증일: 2026-11-01 (Asia/Seoul)

후속 검증: 아래 내용은 최초 프로세스 내부 검증 기록이다. 이후 별도로
격리한 로컬 MariaDB 12.2.2와 실제 HTTP 서버에서 28/28 항목을 통과했다.
Cloudtype에는 접속하지 않았다. 환경·범위·발견 사항·운영 적용 전 절차는
[실제 DB·HTTP 검증 보고서](auth-http-mariadb-validation.md)를 참조한다.

## 범위와 방법

실제 모바일 인증 서비스(`mobile/src/services/auth.ts`)와 컨트롤러를
TypeScript로 변환해 로드하고, 백엔드의 실제 요청 핸들러와 인증 서비스,
실제 bcrypt를 연결한 프로세스 내부 테스트를 추가했다.

전송 계층은 JSON 경계를 모사하는 함수, DB는 메모리 저장소,
SecureStore·AsyncStorage·AppState는 대체 구현을 사용했다. 컨트롤러는
결정론적인 훅 하네스로 실행했다. React 렌더러, StrictMode, 네이티브
라이프사이클이나 화면 렌더링 자체를 검증하는 테스트는 아니다.

테스트 주소는 VM 내부의 예약된 `.invalid` 도메인만 사용한다. 실제 fetch,
HTTP 리스너, MariaDB 커넥션 풀, 마이그레이션 실행은 사용하지 않는다.
백엔드 저장소의 SQL·트랜잭션 검사는 별도의 가짜 connector 테스트에 한정된다.

## 재현 후 수정한 문제

1. 만료 토큰 복원 중 SecureStore 삭제가 실패하면 welcome 화면에 남아
   오류와 삭제 재시도 버튼이 보이지 않았다. 실패 시 로그인 화면을 먼저
   선택하도록 수정했다.
2. 서버는 기존 계정의 짧은 비밀번호 검증을 허용했지만 모바일은 모든
   비밀번호에 8자 제한을 적용했다. 8자 제한은 신규 가입에만 적용하고,
   로그인은 빈 값만 사전 차단한다. 서버의 NUL·72바이트 검사는 유지한다.
3. 보호자 가입의 ROLE_APPROVAL_REQUIRED 응답이 일반 인증 실패로 표시됐다.
   가입 API의 해당 코드만 승인 안내로 매핑한다. 서버의 임의 메시지는
   표시하지 않으며, 다른 401/403은 기존 인증 실패 처리를 유지한다.

기존 lint 오류도 정리했다. SOS 완료 상태 변경은 타이머 콜백 안에서
처리하고, 환자 홈의 아포스트로피는 같은 문자로 렌더링되는 JSX 엔티티로
표현했다. Context의 사용하지 않는 import도 제거했다.

## 검증 항목

- 가입 → 현재 사용자 확인 → 토큰 저장 → 재시작 복원 → 로컬 로그아웃
- 로그인 시 선택한 역할보다 서버의 계정 역할 우선
- 중복 제출 방지 및 인증 로딩 상태
- 만료 토큰 제거, 삭제 실패 표시와 재시도
- 오프라인 복원 시 홈 진입 차단 및 기존 토큰 유지
- 기존 bcrypt 계정의 짧은 비밀번호 로그인
- 잘못된 비밀번호·토큰 저장 실패 시 홈 진입 차단
- 보호자 승인 안내와 중복 이메일 오류
- 빈 로그인 비밀번호·짧은 신규 비밀번호 사전 차단
- 인증 이후 복약 체크, AI 메시지, SOS 카운트다운 상태 회귀 검사

## 재실행

최종 결과: 백엔드 테스트 17건, 모바일 서비스 테스트 7건, 프로세스 내부
통합 테스트 9건으로 총 33건이 통과했다. 서버 구문 검사, 모바일
`npx tsc --noEmit`, `npx expo lint`, `git diff --check`도 통과했다.

두 패키지의 의존성이 설치되어 있어야 한다. 통합 테스트는 mobile-api의
bcrypt 및 Express 의존성을 함께 사용한다. 아래 명령은 서버를 시작하지 않는다.

```text
cd mobile-api
npm test
npm run check

cd ../mobile
npm run test:auth
npm run test:auth-integration
npx tsc --noEmit
npx expo lint
```

## 실제 환경 검증으로 남은 항목

- 실제 MariaDB 버전·스키마·권한·트랜잭션·동시 가입·마이그레이션 호환성
- Express 미들웨어 전체와 실제 HTTP/HTTPS·프록시·시간 제한 동작
- iOS/Android SecureStore 및 앱 종료·재실행·백그라운드 복귀·StrictMode
- 실제 UI 렌더링, 접근성, 키보드 및 기기별 동작
- 기존 계정 이메일 검증·연결과 보호자 승인 절차
- 모바일의 서버 토큰 폐기 API 호출 연결: 현재 모바일 로그아웃은 로컬
  토큰 삭제이며, 서버 세션은 만료 또는 별도 폐기까지 남는다.

이 최초 검증 단계에서는 실제 DB 접속·변경, 서버 실행·배포,
Git commit·push를 수행하지 않았다. 후속 단계에서는 격리 로컬 테스트
인스턴스에만 스키마를 생성하고 HTTP 요청을 실행했으며, 운영 변경·배포와
Git commit·push는 계속 수행하지 않았다.
